## 1. 服务形态（判定适用性的前提）

- 前端：Vue 3 + Vite 6 + vite-ssg 的**纯静态**站点，构建产物是 HTML/CSS/JS。
- 托管：Cloudflare Pages（`wrangler pages deploy apps/web/dist`），由 Cloudflare 托管静态文件，
  **本仓库不运行任何服务端进程**（无 PHP / Java / .NET / Ruby / Python 服务 / nginx / Apache / 数据库）。
- 构建：GitHub Actions（`.github/workflows/deploy.yml`）里 `pnpm install / typecheck / build`。
- 因此：CVE 清单里占绝大多数的**服务端运行时 RCE**对本站不构成直接攻击面；
  真正适用的是 **Node.js 构建/开发运行时** 与 **npm 依赖链**。

### 清单逐项适用性

| 清单分区 | 结论 | 依据 |
| --- | --- | --- |
| PHP 运行时（CVE-2026-109618/109619） | 不适用 | 仓库无 PHP 文件、无 composer.json |
| **Node.js 运行时（111497 / 105482 / 105483 / 106069）** | **适用** | CI 与本地都跑 Node |
| Jetty / Tomcat / MINA / Spring / WebLogic 代理 | 不适用 | 无 Java 工程、无 pom.xml |
| .NET / ASP.NET Core / Kestrel | 不适用 | 无 *.csproj |
| Rails / Active Storage / libvips | 不适用 | 无 Gemfile |
| Starlette / FastAPI / Django | 不适用 | 无 requirements.txt，无 Python 服务 |
| NGINX / Apache HTTP Server / SiteGuard | 不适用 | 托管在 Cloudflare Pages，仓库无 nginx.conf / httpd.conf |
| Plex Media Server | 不适用 | 未部署 |
| Oracle Database / OpenSSL / Micronaut | 不适用 | 无数据库、无 Java |

## 3. 残留（已评估，未修）

### 3.1 unhead ×3（low + 2 moderate）— 传递自 vite-ssg

- 路径：`. > vite-ssg > @unhead/vue > unhead`（1.11.20）。
- 修好需要 `vite-ssg` 0.24.2 → 28.x 的**大版本升级**（新版才用 @unhead/vue v2）。
- **可达性：不可达。** 本站从未调用 `useHead` / `useHeadSafe`（全仓 grep 仅剩 vite-ssg 内部的
  `createHead()`），漏洞点（useHeadSafe 属性注入 / URI scheme 绕过）没有入口。
- 顺带清理：删掉了本项目**重复**的 `@unhead/vue` 直接依赖与手写 `createHead()`
  （vite-ssg 默认 `useHead: true` 已自行安装 head，重复安装两个实例本来就是多余的）。
- 为什么不在本次升级：vite-ssg 28 会改变客户端启动路径（hydration 语义），
  而 AGENTS.md §5 #40 记录「本仓库客户端是整树重渲染」，启动帘幕的头像归位交接依赖这一行为。
  在安全补丁里做框架大版本升级属于高风险变更，应单独开任务并配视觉回归。

### 3.2 braces（high）— 传递自 unocss > chokidar

- **无已发布修复**：advisory 要求 ≥3.0.4，但 npm 上 braces 最新只有 3.0.3。
- 仅构建期使用（chokidar 监听本项目源文件），glob 模式是静态写死的，
  不接收外部输入 → 不可达。

### 3.3 sprintf-js（moderate）— 传递自 gray-matter > js-yaml > argparse

- **无已发布修复**：advisory 要求 ≥1.1.4，npm 上最新 1.1.3。
- 仅构建期解析本项目自己的 frontmatter，格式串不来自外部 → 不可达。
